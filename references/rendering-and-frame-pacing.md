# 背景、材质与稳定播放：F1 Final J 实例

用于已有 WebGL 演示的背景细节、光照、材质、远景闪烁、阴影和卡顿。
保护已认可的相机、对象路径和阅读落点。数值来自 F1 的 Three.js r186
实现；小型机制实验室继续使用自己的固定版本，不据此整体迁移。

## 背景要形成场所

检查实际播放机位，尤其是开场 0 秒、中段和 3D→PPT 淡出中间帧。
近树、林缘、远林共同形成纵深，不能仅在车旁种几棵树，留下空旷地平线。
避免巨大的球形树冠或绿色贴片挡住后景；树干和树冠一起按合理尺度变化。
小树仍需可辨的树皮、UV 密度和法线，不能只是一根纯色细棍。

看台需要接地的周边铺装、地基与连贯场地关系。高度正确的孤立几何也会
像旷野中的小岛。端墙收边，中间的重复黑隔板却会切断座椅与场所关系。
不要为增加细节补回已删掉的铁架、漂浮旗帜和用户不要的观众。

草地采用两层尺度：低对比度的 color/normal/roughness 基底，以及近景
有高度的实例化草丛。按实际相机可见区域分配密度，避免草侵入道路。
道路、路肩、草区共用赛道坐标，特别检查最靠赛道的细长草带是否漏种。
将种植与材质规则同步到其它赛道布局，不能只改开场。

## 先区分表面信息和照明

纯色混凝土只改 roughness 仍会像塑料。先核对材质分类的实际命中数、
图集 alpha、color/normal/roughnessMap，再调灯。不凭名称猜测全部玻璃
已被修改，也不要把贴花、轮胎和碳纤维归入车漆。

| 对象 | 有效信息 | 常见误区 |
|---|---|---|
| 车漆 | 底漆响应与更锐利的清漆反射 | 全车 metalness 拉满或只加饱和度 |
| 玻璃 | 暗底、掠射反射、保留窗框图集遮罩 | 整片透明化，窗框一起消失 |
| 混凝土 | 低对比颗粒、粗糙度和法线变化 | 强自发光抬平背光面 |
| 干沥青 | 细骨料、胶痕和粗糙度下限 | 黑贴图区域变成湿亮镜面 |
| 天空 | 足够精度、统一方向、真实 HDR 照明来源 | 可见天空照片代替 HDR 环境光 |

F1 车漆使用底层 roughness .39、clearcoatRoughness .075，是该资产下的
参考，不应套给全部材质。先看反射带的形状和层次，再决定参数。

环境图可能同时贡献镜面与漫射；显式材质 envMap 的强度路径也可能不同
于 scene.environmentIntensity。核对固定版本的 shader，不把 PMREM、
SH、Hemisphere、Ambient 当成互不相关的亮度旋钮。J 的 SH 替代部分
均匀补光，能量近似不变，所以视觉开关差异很小：有实现不等于有明显收益。

反射应有天空、地平线、场地和建筑的结构。加载时在代表位置捕获带阴影
的 cubemap，使用 HDR 天空源并预滤；避免逐帧重新捕获。只有错位仍明显
时再增加局部探针。J 的新探针仅替代目标材质镜面采样，保留已平衡的
漫射链，增加约 6 MiB；这是预计算反射，不是光追或每帧全屏 GI。

## 讨喜的画面与干净的 PPT 落点

先修几何、光比、反射与材质，再调色。F1 的 `broadcast` 在现有世界合成
中轻提选定中间调、让受光暖面略暖、柔化高亮区，没有新增滤镜 pass 或
统一拉高饱和度。权重随世界淡出归零，不污染照片、DOM 文字与阅读页。

核对 target 的色彩路径。AO 乘在 tone mapping 后会同时压暗清漆高光。
能调整时优先在线性 HDR 中处理；保留旧链路时可减轻高光受 AO 的影响，
但应写清近似。不要未验证当前版本就依赖 `isXRRenderTarget` 等内部行为。
相同机位保留旧参数作 A/B，看高光形状、背光色偏和主体层次。

## 三类闪烁分别处理

1. 灰/深灰表面交替：查重复面、共面补体与深度精度。
2. 叶片/铁网运动中消失：查 alpha cutout 和 mip 过滤。
3. 车不动但转镜头就换阴影：查影图焦点、投射者集合与 shadow LOD。

### 树叶 mip alpha

J 三张 1024² 叶片贴图在 2×2 mip 的最大 alpha 为 60、79、85（0–255），
都低于 .38×255。固定 alphaTest 会裁掉整级；动态模糊无法补回丢失覆盖。
可按 UV 导数的像素足迹，在远景逐渐改用过滤 alpha 的 MSAA 覆盖，近景
保持裁剪边缘。条件是启用 MSAA、世界后面有不透明天空，且世界合成不把
coverage 当成整幅画面透明度。单采样环境捕获要恢复原裁剪，避免矩形。
这不同于把所有树改为 `transparent=true`。实际实现：
[material-light-j.js](https://github.com/Rayman0106/f1-economics-3d-deck/blob/main/src/j/material-light-j.js)。

### 稳定影图

旧开场按画面中心选车，车阵静止时影图中心在 0.1 秒内就能跳约 35 m。
提高分辨率或 PCSS 不能修复这种焦点跳变。改用实际车阵范围中点；检阅
则沿编排好的连续 light-focus 路径。给同一镜头固定投影范围并留边界余量，
不要逐帧随取景缩放。对投射者避免突然跨半径阈值，对 shadow LOD 避免
随镜头变焦切换几何。光源基底中的纹素对齐示例：

```js
// 向量均为世界空间，right/up 与归一化光方向构成正交基底。
const px = width / shadowMapWidth, py = height / shadowMapHeight;
const x = centre.dot(right), y = centre.dot(up);
centre.addScaledVector(right, Math.round(x / px) * px - x);
centre.addScaledVector(up, Math.round(y / py) * py - y);
```

车阵、光源、背景和影图身份都未变化时复用静止影图，改变状态则失效。
J 开场 160×116 m/4096²，后续恢复 60×52 m；范围须按实际车阵、阴影
长度与边界重新选，不能作为其它项目常量。缓存与失效的完整实现：
[surface-j.js](https://github.com/Rayman0106/f1-economics-3d-deck/blob/main/src/j/surface-j.js)。

## 60fps 仍卡：串行工作和节奏

记录 CPU 提交、draw calls、P95/P99/最长帧间隔及首播/重复播放差异，
不要只看平均 FPS 或 GPU 功耗。GPU query 可能含供给等待，不等于活跃率；
CPU/GPU 流水有重叠，也不能直接相加。

先减少重复静态世界矩阵更新、树遍历、包围球/视锥计算与大量小阴影网格
提交。缓存需要场景坐标框架变化时显式失效；不能冻结会动的节点。
合批刚性阴影时保留真实世界变换、轮胎滚动/转向及透明材质的原路径。
代码见 [performance-j.js](https://github.com/Rayman0106/f1-economics-3d-deck/blob/main/src/j/performance-j.js)。

Worker 适合纯数据的 LOD、几何合并、遮挡和字形预计算，传 typed arrays，
不传 DOM/renderer。J 最多 6 个 Worker，准备完成释放；主线程 WebGL 不会
自动使用 16 核。多核不能直接消除 GPU 像素、驱动或浏览器合成瓶颈。

用绝对时间限制提交，错过时隙跳到未来时隙，不补画一串帧。剧情保持
`seconds=(now-start)/1000`，不每帧加 1/60，也不按 range 控件的 .01 秒
步长量化真实时间。参见
[playback-j.js](https://github.com/Rayman0106/f1-economics-3d-deck/blob/main/src/j/playback-j.js)。
WebGL 项目不能声称开一个选项就能使用 DLSS；先核对平台接口和收益。

## 全屏尺寸之后、剧情时钟之前预热

shader 数量未变但首播仍卡时，检查纹理上传、target 分配、尺寸变化与
逐帧 reset，不直接归因于 shader 编译。

1. 加载时准备真实材质、阴影、LOD 和世界/前景合成变体。
2. Start 手势内发起全屏和音频解锁，待尺寸稳定再应用最终 DPR。
3. 尺寸已热好则跳过重复准备；尺寸变了，实际绑定、清除和渲染所需 target，
   包括稍后淡出才用的前景 MSAA 缓冲。
4. 热好代表机位后复原状态，再记 Start 时间。`gl.finish()` 如需使用，
   只留在准备边界，不放每帧。
5. 连续播放保留场景；包含 reset 的手动 seek 不适合逐帧播放。

实际分辨率读 `gl.drawingBufferWidth/Height`。CSS 尺寸、4K 显示器、
视频输出尺寸与 3D 缓冲尺寸分别报告。

## 验证与正式发布

J 一次 2400×1350、1,858 帧实测：均值 59.99 fps、P95 17.7 ms、最长
40.4 ms。167 个静止影图样本有 166 次复用。前者仍含尾部尖峰，后者是
数值证据；观感需正常速度播放，不能据此宣称跨设备无卡顿。

正式版排除对照面板和 profiler，保留模型、背景输入、来源许可与可重建
代码。实测单 HTML 的 Worker、Start、声音和 3D→PPT 端点；旧宣传图标明
版本。不要为了发布复制全部历史工作目录。详见
[Final J 发布说明](https://github.com/Rayman0106/f1-economics-3d-deck/blob/main/docs/FINAL-J.md)。

可直接给 AI 的请求：

> 在开场、中段和淡出机位区分几何、纹理、照明与采样问题，优先做收益
> 最大的两项；记录真实缓冲尺寸和首播帧间隔，最后交付不依赖旧目录的
> 离线成品与源码。
