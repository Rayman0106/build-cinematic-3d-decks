# 可重建工程、离线 HTML、清理与 GitHub

## 区分源码、正式产物和共享资产

```text
src/       可编辑内容、场景、相机、字体、声音
assets/    不可变模型、图片、字体与资产清单
vendor/    固定依赖及许可证
tools/     构建与验证
docs/      说明、来源、讲稿、关键验证记录
build.py   生成离线 HTML
```

大资产不按每个版本复制；共享一套，不在硬链接原位修改。版本差异保存构建代码与必要记录。正式包带启动 HTML、完整许可、构建入口和运行方式，不带缓存、重复视频、私人聊天或没用的历史 QA。

文件结构服务真实工程，不强制所有旧项目迁移。迁移后修正 import、构建路径、工具调用和 source manifest；不能只把文件挪到 src 就提交。

## 单 HTML 与开发版

开发版可以共享本地资源，但 file:// 下相对 ES module/fetch 常受安全限制；正式离线包将所需模块、字体、图片、模型按已验证形式内嵌。Three.js importmap/data module 方案应在目标浏览器测试，不能因 HTTP 预览正常推断双击也正常。

可保留 dev/release 构建选项：开发有 seek/debug，正式只保留用户要的导航。按钮删除是 UI 变化，播放逻辑和 keyboard 可继续存在。Start 后先完成全屏尺寸，再开时钟，避免第一帧错位。

离线资源不代表联网可高效：数百 MB HTML 首包很重、内嵌 base64 有开销、不能逐资产缓存。网页部署时可分拆 GLB/纹理、压缩、CDN、渐进场景加载和设备质量，但这属于另一次已授权部署工作。

## 自动录制与媒体证据

不要默认每轮给用户录视频。需要时区分内部短段检查与用户交付。记录分辨率是 renderer draw buffer 还是1080p输出、帧率是采样/编码还是实际平稳播放、声音是否关闭。60fps标签不能证明实时播放60。

发布示例可用历史录制/GIF，但标明版本、来源和局限。静帧交叉淡化视频叫 slideshow，不冒充真实动画。新实验室明确为机制示意，不与原成品混淆。

## GitHub 开源包

用户授权后再创建/上传/改公开状态。先检查：

- README 有入口、效果图/动图来源、构建方式、项目布局和许可范围。
- `LICENSE` 覆盖原创代码，`THIRD_PARTY_NOTICES` 列资产/依赖，不把整个仓库所有素材自动 MIT。
- 扫描个人绝对路径、账号凭据、cookie、临时授权码和私人材料。公开源文件不得包含原始 Mixamo 动作等不允许再分发的内容。
- 公共素材说明具体哪份 GLB 的作者许可；不上传不必要 Blender/FBX。
- 大成品放 Release，源码目录保持可浏览。删除大文件但留在 Git 历史仍可能公开；发布前处理历史边界，保留必要私人档案，不擅自 force-push 用户历史。
- 上传后核对 commit、Release asset digest、公开状态与匿名访问；README 链接指向实际文件。

本次两个案例保留完整私有历史，再发布干净源码；这是针对旧历史含原始动作的方案，不是所有项目都要复制仓库。公开源码的替代动作与正式成品有差异时写清楚，不偷改已批准的成品。

## 清理

先列具体候选、大小、用途、构建依赖和保留项。用户批准范围后验证绝对路径在目标目录内，用一个 shell 的原生文件操作删除。保留唯一正式产物、必要源资产、构建代码、许可和关键记录；清理前先检查没有运行中的程序占用。不要为了整理顺手删用户桌面上无关目录。

发布最终给出：仓库/Release 链接、如何运行、改了什么、验证范围、仍需用户检视什么。不要给未经播放的作品写“像素级自然、无卡顿”。
